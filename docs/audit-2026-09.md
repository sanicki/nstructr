## Accessibility

### Automated (axe-core)

Run on: Workouts, the workout editor, the exercise settings dialog, Add exercises, Exercises (all and one
collection), the exercise page (with and without its controls), Edit (words, and poses in Authoring mode),
Settings, Create with AI, Share, and on the cover screen (360 × 398) Workouts, the player (with and without its
controls) and a rest. Each in light and dark.

| Rule (impact) | Where | Fix |
|---|---|---|
| `label` (critical) | the hidden file picker had no name | `aria-label="Choose JSON files to import"`, out of the tab order |
| `landmark-one-main` (moderate) | no `<main>` | the views now sit in `<main id="content">` |
| `region` (moderate) | the file picker sat outside any landmark | moved into `<main>` |
| `heading-order` (moderate) | on phones the exercise's `<h2>` name was `display:none` (it's in the top bar), so About's `<h3>` followed the `<h1>` | the name is visually hidden instead of removed, so screen readers keep the outline |

### Touch targets

Material 3 asks for 48 × 48 dp touch targets, even where the visible control is smaller (40 dp buttons,
32 dp chips). WCAG 2.2 AA (2.5.8) only asks for 24 px, so these all passed WCAG before; they now meet M3 too.

- Buttons, chips, segmented buttons and icon buttons get a transparent `::after` that makes the touch area
  48 px tall (and at least 48 px wide) without changing how they look.
- Segmented buttons no longer use `overflow:hidden` (it clipped that area); their end buttons round their own
  corners instead.
- Filter chip rows have 8 px above and below, so the chips' touch areas aren't clipped by the scrolling row.
- Number fields in steppers, the block name field, text fields (56 px, the M3 filled text field), and the
  collapsible Steps and "Name, description and instructions" headers are now at least 48 px tall.

### Keyboard and screen readers

- **Leaving a workout needed a 0.8 s press-and-hold on ✕.** Enter on a focused ✕ worked, but a screen reader's
  double-tap (TalkBack, VoiceOver sends a click with no press) only showed "Hold ✕ to exit", so a blind user
  couldn't leave. Fixed: such a click exits, and **Esc** leaves the workout too. A quick tap with a finger still
  only shows the reminder.
- Tab order on every screen follows the reading order; exercise cards open with Enter; Space pauses on the
  exercise page and in the player; focus is always visible (a 3 px outline).
- Dialogs: focus moves into them and Esc closes them. The new confirm dialog puts focus on Cancel.
- `prefers-reduced-motion`: animations don't start by themselves, transitions are off, scrolling doesn't glide.

## Material Design 3

| Found | Fix |
|---|---|
| Deleting a workout, a block, your own exercise, discarding edits and clearing history used the browser's `confirm()`: not M3, can't be themed, and some in-app browsers block it | `ask()`: an M3 basic dialog (headline, supporting text, Cancel + a filled action, red for destructive actions) |
| No `--md-on-error` colour token | added for light and dark (#ffffff / #690005) |
| Settings → Import & tools used large cards with icons, unlike every other Settings group | rows, like the rest of Settings |

Checked and in line with M3: the colour scheme (tonal spot from the icon's blue, light and dark), type scale
(Roboto Flex; display, headline, title, body, label roles), shapes, the navigation bar and rail, top app bar,
filled/tonal/text buttons, filter chips, segmented buttons, switches, filled text fields, snackbar, basic and
full-screen dialogs (headline-small vs title-large titles), state layers (8 % hover, 12 % pressed).

Deliberate departures, kept:
- The workout player isn't an M3 screen: it's a full-screen, glanceable display for the floor, with very large
  type and controls that only appear on a first tap.
- On short screens the navigation bar moves into the top app bar (icons only), to keep clear of the Flip7's
  cover-screen cameras.

## UI consistency

- "Add it" (Create with AI) → **Add**, as in Add exercises and shared links.
- "Paste exercise JSON" → **Paste JSON** (it takes workouts and backups too).
- Settings order: Documentation, Workouts (rest between exercises, rest between sets, sound, full screen),
  Display, Create with AI, Import & tools.
- Confirmations now all look and read the same: "Delete "…"?" + what happens + Cancel / Delete.

## Layout

The audit now also fails any screen that scrolls sideways. It caught one at once: two leftover CSS rules for a
`main` element (from an early layout) started applying when `<main>` was added, making the Exercises tab
1256 px wide. The rules were removed.

## Security

Shared links and imported files are untrusted. A probe (`tools/e2e/security_imports.py`) puts an HTML/script
payload in every text field of an exercise and a workout, imports it, and walks every screen, the editor, the
exercise page, the workout player with Coach speech, a share link and opening it:

- **No HTML or script ran**: every text goes through `esc()` or `textContent`.
- **Found:** `source.url` was shown as a link whatever its scheme, so a shared exercise could carry
  `javascript:…` and run it when tapped. **Fixed:** only `http(s)://` links are shown.

Also checked: share links carry only JSON (parsed, never evaluated); imports go through the same validation as
files; ids from outside can't overwrite the user's (`claimIds`); nothing is sent to any server.
